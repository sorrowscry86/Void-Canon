# Stage 4 — deferred complementary integration

## Context to supply

Only begin after the user accepts Stage 3. Send `PRODUCT-BRIEF.md` and the latest implementation handback. The studio must remain independently useful on Android; the user's existing local tools/APIs are optional complements. No actual tool endpoints have been selected or authorized by this document.

## Outcome

Prove one explicit exchange: selected approved world material goes to one chosen tool, and a returned asset becomes a linked reference in the studio.

## Work

1. Ask which actual tool and task to connect. Establish endpoint, authentication, costs, supported formats, and Android reachability. Do not assume a phone can reach a PC's localhost, and do not expose a local service publicly by default.
2. Begin with a portable manual exchange if that meets the user's need: export a character/setting reference package and import the resulting asset. Automated networking is optional.
3. Keep outbound context narrowly selected and inspectable: approved appearance, chosen reference images, pertinent lore, and the specific task. Do not include unrelated secrets, operational agent memory, or credentials.
4. Keep external actions explicit. Capture returned asset provenance and source entity links. Importing an image does not automatically change canon or character appearance.
5. Handle disconnects, retries, duplicate imports, cancellation, and cost disclosure appropriate to the chosen service.

## Acceptance

- Show exactly what material is shared and which tool receives it.
- Return one asset, review it, and attach it to the intended entity without overwriting the baseline.
- Disable or disconnect the integration; local world editing, references, stored RP, and chapters continue working.
- Backups retain the resulting asset and provenance but not secrets.

## Stop boundary

No generalized automation platform or broad infrastructure access. Summarize the demonstrated contract and its limitations in the implementation handback. Further integrations and productization require a new scoped task.
