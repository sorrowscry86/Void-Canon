# Regular 0.6.2 — release evidence

## Problem and resulting behavior

After 0.6.1's direct JSON-mode change, the user still reported story/state rejection on DeepSeek and similar failures on OpenRouter, and requested looser formatting. The shared repository previously required the whole state protocol before publishing any story. `StoryResponse` now accepts usable prose/common wrappers independently of optional state; full validation remains required before changing tracked facts. Prompts prefer the protocol but explicitly permit prose, and direct DeepSeek no longer forces JSON mode. Completed fallback turns retain a nonfatal warning in diagnostics and the small Play footer; subsequent context identifies the recent state/transcript gap. No extra API call, repair, retry, provider/model switch or price change is introduced. User phone outputs were unavailable; this addresses the shared format dependency without claiming to reproduce a particular private payload.

## Build and unit verification

[Clean build of the parser/storage implementation](clean-build.log): JDK 17, SDK/build tools 35, pinned Gradle 8.11.1. `clean assembleDebug testDebugUnitTest lintDebug assembleDebugAndroidTest --continue --no-daemon '-Dorg.gradle.jvmargs=-Xmx1g -Dfile.encoding=UTF-8'` passes in **8m**, all 82 tasks executed. Lint reports no issues. **121 unit tests pass with zero failures/errors/skips** ([per-suite totals](unit-summary.tsv)). This clean build verifies the parser/storage changes; a later display-only adjustment suppresses the fallback snackbar while retaining the footer notice. A test-only return-to-Play step was corrected afterward; the [follow-up test-artifact/lint build](test-followup-build.log) passes in **1m 52s**, 55 tasks (8 executed, 47 up-to-date).

[Final outgoing build](build.log), after the display-only suppression: **passed in 6m 58s**, 81 tasks (22 executed, 59 up-to-date). It reruns all **121 unit tests with zero failures/errors/skips**, lint and both APK builds. Lint reports no issues. The final production APK matches the signed-upgrade summary.

New coverage includes prose and one-word replies, common wrapper aliases, fenced JSON/CRLF, missing/wrong state fields, stale/unsupported metadata without state application, malformed/truncated/oversized output, thinking-block exclusion, idempotent narrative-only completion, matching-draft consumption, restart/ZIP retention of story and warnings, guarded native facts/mechanics, and gap notes in subsequent context. Existing strict state tests and stale fingerprint/cancelled completion protections remain in the full suite, alongside storage/migrations/backups, image, routing and speech checks.

An [initial build](initial-word-reply-failure.log) rejected a one-word “Yes.” fixture. The parser was adjusted to distinguish prose literals from JSON booleans/null/numbers and the final clean run above passes. No candidate from the failed run is distributed.

## Limits

No physical Galaxy S26, real DeepSeek/OpenRouter key or live inference was used. Both-provider fixtures cannot prove that every live model supplies usable prose, current model access/prices or narrative correctness. There is no automatic replay/salvage of prior failed turns. Empty/unusable output, unfinished reasoning, output-budget termination, provider errors and changed-scene fingerprints remain failures. A narrative-only turn does not update tracked state; inspect the saved notice and correct continuity when appropriate. A later valid protocol reply resumes normal strict state updates, without guaranteeing semantic completeness. No artwork pipeline, voice implementation, schema, campaign engine or account-sharing policy is changed. Older Android results are historical, not claimed as rerun on this patch.
